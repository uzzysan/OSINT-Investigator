# 09: Entities, properties and tags

**What to build:** the core act of the whole application — an analyst records a
finding. Choose a Schema, fill in Properties, and it becomes a node in the Case.

A person gets five phone numbers without anyone choosing which one is real,
because Properties repeat. The caption appears automatically from the Schema's
template so nothing needs naming by hand, and can be overridden when the node
should be labelled the way the analyst thinks about it. A confidence flag —
confirmed, probable, hypothesis — is present from the first write, so a guess is
never later mistaken for a fact by the analyst or by anyone reading their report.

Ids are generated by the caller. An agent can build a whole subgraph locally and
submit it in one piece, which is what makes batch writing possible later.

Validation errors state what was wrong and what to send instead. That phrasing is
for a model to act on without a round trip to a human, and is worth the extra care
now because every transport in the next spec inherits it.

**Blocked by:** 07, 08

**Status:** ready-for-agent

- [ ] Create an Entity from a Schema and a set of Properties
- [ ] Properties repeat, preserving their order
- [ ] Each value stores both the raw input and its normalised form
- [ ] The Case's default region is applied when normalising region-dependent values
- [ ] Captions derive automatically and can be overridden
- [ ] Confidence is set on creation and can be changed
- [ ] Tags can be attached, detached and listed, scoped to the Case
- [ ] Read an Entity with its Properties; list and filter Entities within a Case
- [ ] Update Properties by adding, replacing and removing values
- [ ] Soft deletion is reversible within the retention window; purge destroys
- [ ] A merged-away Entity still resolves by its original id, indicating the survivor
- [ ] Caller-supplied ids are accepted; a duplicate is rejected with a clear error
- [ ] Validation failures name the offending Property and state what a valid value looks like
- [ ] Checksum warnings surface on the created Entity rather than being discarded
- [ ] Every mutation is audited with its Actor, in the same transaction
